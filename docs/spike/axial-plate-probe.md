# Plan 12, A0: what OFFBEAT does with an axial stack and with a plate

Done 2026-10-14 for [plan 12](../plans/12-axial-stack-and-plate.md), milestone A0, through the real solver (feed-solver distro, OFFBEAT `80e84450`, OpenFOAM 9). **Gate met: every unknown of the plan is answered below and the plate runs, so the plan does not stop for the user's decision on an independent-only plate solver.** The probe is a set of throw-away scripts that take a case FEED's writer wrote and edit its files (kept as `.txt` in [axial-plate-probe/](axial-plate-probe/)); no FEED source was changed. Every case is the synthetic pin of `examples/synthetic-pin.json` (fuel k 3, cladding k 15 W/m/K, gap 5000 W/m2/K, film 30000 W/m2/K, coolant 573 K, 20 kW/m average) on the mesh 20 fuel / 6 cladding cells, unless stated.

## Things the plan did not know

- **The stack is one OFFBEAT run, and it includes axial conduction.** Decision 3 of the plan ("N separate one-slice runs, no heat between slices") is replaced by: one run with N axial layers per solid, whose result is the (r, z) solution. The measured effect is small and goes as 1/L^2 (table above); it is **not** zero, so the per-slice independent solutions of FEED differ from the stack by that amount and the cross-check needs a bound that includes it (A1: a conservative bound from the geometry and conductivities, calibrated on these measurements; a later option is a two-dimensional independent solution).
- **Cell order.** The cells of the result are written block by block: all fuel cells (layer by layer, radial index fastest), then all cladding cells in the same way. For N layers and nf, nc cells per layer, fuel cell (layer k, index i) is number k nf + i and cladding cell (k, i) is number N nf + k nc + i. FEED's parser reads the one-layer case as "fuel then cladding" and must be given N.
- **The starting field** of a steady start is written for every cell; it must be written in the same order (the writer's per-slice steady solution at each slice's heat rate).
- **The axial coordinate of the power profile is normalised (0 to 1), the one of the boundary table is in metres.** Both start at the bottom of the mesh.
- **A plate needs `angularFraction` in `globalOptions`** because it has no wedge patches; nothing else was needed (`reactorType` stays `LWR`, `sliceMapper autoAxialSlices` is fine for the stack, `empty` faces replace the wedges). The heat rate keyword is then per metre of height **and per the plate's width in y**: q''' = lhgr / (fuel width x half-thickness), as the closed form above confirms. The writer must pick the width (1 m is the clean choice, so lhgr is the heat per metre of height per metre of width).
- **OFFBEAT can compute the coolant temperature along the pin itself.** The tutorials `test_coolantChannel/generic_pwr_1D_enthalpyModel` and `generic_pwr_1D_coolantTemperature` do it (an enthalpy balance). This plan keeps the coolant profile as an **input** (the user, or NODAL, supplies it); the enthalpy model is a possible later option and was not tried here.
- **Speed.** A 10-layer stack runs in about a second, like the one-layer case; threads are not needed for the stack (they were in the plan only for separate runs).
- OFFBEAT still exits 139 after complete output on every run, as before.

## Consequences for the plan

1. The stack is **one run**; the writer changes the mesh (N layers per block, height L), writes the power profile (normalised) and the axial boundary table, and the parser reads N layers. The end faces stay `empty`.
2. The "no heat flow between slices" statement of the plan becomes "the solver includes the axial conduction; the checks bound it". The bound and its calibration are an A1 task.
3. A plate is supported by OFFBEAT (steady, transient, stacked): decision 4 goes ahead with a Cartesian mesh and `angularFraction 1`. Not probed: a plate with mechanics or burnup (both stay out of scope), a plate cooled on both faces (two coupled outer patches: the symmetric plate with the adiabatic plane at x = 0 is the same problem, so the first version needs only that), and a plate with a boundary history (the same boundary types as the pin, expected to work; A4 checks it).
4. The checks per slice use FEED's one-dimensional independent solutions at each slice's heat rate and coolant, so A2 needs the bound above and the 1/L^2 scaling as its tolerance.
