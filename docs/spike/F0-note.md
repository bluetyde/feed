## Upstream example run: `Cases/testCases/generic_pwr_1D`

A generic PWR rod, one axial slice, 410 cells, run to 3.15e7 s (122 time steps), 6 s wall, serial. Inputs are generated by the case's own `rodMaker.py` (a symlink into `tools/rodMaker/`; copy the case with `cp -rL`) from `rodDict`, then `blockMesh`, then `offbeat`.

- **It is a full fuel-performance model**, not a thermal pin: LWR materials, burnup (Lassmann), fission-gas release (SCIANTIX), FRAPCON gap gas, small-strain mechanics with creep and plasticity, time-dependent power. FEED must select a thermal-only subset.
- **Determinism**: two independent runs gave byte-identical `31500000/T`, `Bu`, `D` and the probe file `postProcessing/probes/0/T`.
- **Output**: one directory per written time (`0`, `25547802.49`, `31500000`), each holding about 129 field files (`T`, `D`, `Bu`, ...) as ASCII cell lists, plus a probe file with time and temperature at the sampled point. Temperatures in the final fuel cells are about 980 to 1020 K.
- **No upstream expected output was found** in the repo for this case, so "matches the upstream expected result" is **not** established. What is established is determinism and plausibility, not correctness.

## Shutdown crash (important for the run manager)

OFFBEAT finishes all time steps and writes the final time, then **segfaults at process exit (exit 139)** and never prints the `End` line the README says to check. A gdb backtrace puts the crash in a global destructor (the `volFields_<Vector>` PtrList, destroyed after its registry) during `__cxa_finalize`, not in the numerics. The cause is not investigated further; it may be specific to this commit, this compiler or this build. **Consequence: a run is `completed` only if the expected final time directory exists with finite fields, never by exit code or by the `End` string.** This matches ARCHITECTURE's existing rule.

## Thermal-only is possible

`mechanicsSolver fromLatestTime;` switches mechanics off (D is read from the initial time) and `fgr none;` switches fission gas off. The `generic_pwr_1D` case with only those two edits runs to the final time in about 1 s. Valid values come from the solver's own error text and from its docs (`mkdocs/docs/user_guide/solverDict/`). Not yet tried: switching off burnup and fast flux, which change material properties through the run.

## How a 1D pin is represented

A wedge mesh from `blockMesh` (patches `fuelInner`, `fuelOuter`, `cladInner`, `cladOuter`; `.*Front|.*Back` are `wedge`; top and bottom are `empty` for `geometryType 1D`), one cell azimuthally, radial cells per block set by `nCellsR`. The fuel-cladding gap is a coupled patch pair (`fuelOuter` of type `fuelRodGap`, `regionCoupledOFFBEAT`), not a mesh region; it uses the gap-gas model (`gapGas FRAPCON`) and a roughness. ## Thermal oracle case (done 2026-10-05)

A thermal-only OFFBEAT case reproduces the closed-form oracle. `solver/make-oracle-case.py` writes it from a parameter file (this is the seed of the case writer).

| FEED quantity | OFFBEAT expression |
|---|---|
| geometry | `rodDict` radii in mm, one fuel block, one cladding block, one axial cell, wedge 0.25 degrees (`rodMaker.py`, `blockMesh`) |
| constant conductivity | `materials { fuel { material constant; k k [1 1 -3 -1 0] 3; ... } }` in `constant/solverDict` (all other `constant` properties must be given too) |
| uniform power q' | `heatSource constantLhgr; heatSourceOptions { lhgr 20000; axialProfile { type flat; } radialProfile { type flat; } materials ( fuel ); }`. The field `Q` came out uniform and within 3e-6 of q'/(pi R^2) |
| constant gap conductance | on both coupled patches in `0/T`: `type resistiveGap; patchType regionCoupledOFFBEAT; coupled true; kappa k; alpha uniform 5000;` (applies at the fuel surface; checked) |
| convective boundary | `cladOuter { type convectiveHTC; T0 uniform 573; h uniform 30000; value ...; }` |
| fixed surface temperature | `cladOuter { type fixedValue; value uniform 294.35; }` |
| thermal-only | `mechanicsSolver fromLatestTime; neutronicsSolver none; elementTransport none; burnup none; fastFlux none; gapGas none; fgr none;` |

Results (saved in `solver/results/`, tested in `tests/offbeatOracle.test.ts`):

- Synthetic pin, four meshes: maximum fuel error 1.386, 0.455, 0.137, 0.037 K; error ratios 3.1, 3.3, 3.7 per doubling, approaching second order. Cladding error at most 0.04 K. Outer wall 595.338 K against 595.3375 K from the closed form. Every mesh is inside the 5 dT / N^2 bound that was fixed for the independent finite-volume check before this solver ran.
- Sourced K-State TRIGA hot element (zero cold gap, effective gap conductance 2840 W/m2/K, 40 fuel cells): the first fuel cell is 776.17 K against the SAR's published 503.2 C (776.35 K), inside 0.5 K.
- **Steady state needs a long end time.** The first runs stopped at 2000 s; OFFBEAT took two steps (1 s, then one implicit step of 1999 s), and the leftover heat-storage term left the fuel about 0.5 K cold with errors that did not shrink under refinement. At 5e7 s the problem is gone. Those first runs were discarded. The case writer must use an end time well beyond the slowest thermal time constant.
- OFFBEAT's `heatFluxSummary` (a diagnostic) reports boundary power about 0.05% below the input; the run with the wall temperature at the closed-form value shows that this is a diagnostic effect, not missing power. Not investigated further.
- The tolerance gate (`5 dT / N^2`) was fixed earlier for the independent finite-volume check, not tuned on these results. The refinement gate (error ratio above 2.5 per doubling) was set after the runs and is recorded as such in the test.

## Temperature-dependent conductivity (done 2026-10-05)

OFFBEAT's conductivity models are selected per material with `conductivityModel <name>;` next to `material constant;`. There is no generic linear or table model. The named correlations (`steel1515TiTobbe`, `SwindemanHastelloyN`: linear in degC; `ZyRELAP`: cubic in K with a stated 290 to 1800 K range; Molybdenum: quadratic; several UO2 models) read optional coefficient overrides from a `conductivity { par1 ...; par2 ...; }` block. `steel1515TiTobbe` is `k = par1 + par2 * (T - 273.15)`, so `par2 = b`, `par1 = a + 273.15 b` gives any `k = a + b T`.

Check: fuel k = 4.0 - 0.0006 T, the rest of the synthetic pin unchanged, four meshes, steady state. Maximum fuel error against the conductivity-integral solution (centre 1246.8586 K): 1.372, 0.368, 0.113, 0.035 K, ratios 3.73, 3.26, 3.25. Outer wall 595.338 K as for constant k (same flux, same film). Saved in `solver/results/synthetic-pin-kT.mesh1..4.json`; the writer-produced run is golden in `tests/golden/offbeat-kT/`.

Cautions: (1) OFFBEAT does not enforce a stated range; FEED flags a result out-of-domain itself. (2) The `Tobbe` name is a misnomer for a generic linear law; this relies on the coefficient-override block existing in this OFFBEAT commit. (3) Only linear laws are wired; cubic (`ZyRELAP`) and tabulated laws are not.

## Non-convergence probe (2026-10-06)

Script `solver/probe-nonconvergence.sh`, evidence `solver/results/nonconvergence-probe.json`, test `tests/nonconvergence.test.ts`. Pinned stack, the synthetic pin on mesh 1.

**How OFFBEAT decides** (read in `offbeat/offbeat.C:330-345` and `thermalSubSolver.C converged()`): each time step runs `do { outer iteration } while (nOuterIter < 2 || (!converged && nOuterIter < maxOuterIter))`. Thermal convergence is `absErrT <= absErrT tolerance` (default 0), or else `(initial residual < T and relative residual < relT)`, or either 10 times below its threshold. The case writer leaves `maxOuterIter` at 1000, `T` 1e-5, `relT` 1e-6, and sets no `absErrT`.

**What happens at the cap:** nothing. The loop simply ends, the step is accepted, written and the run goes on. With `maxOuterIter` 2 and a single 1 s step from the 900 K initial state, the last outer iteration had `absErrT` 11.16 K and relative residual 0.039 (criterion 1e-6): not converged. OFFBEAT wrote time 1, printed no warning or error about the limit, and exited 139, exactly as the converged reference run (6 outer iterations, `absErrT` 8e-8) did. The unconverged field differs from the converged one by up to **6.5 K** (at r = 3.9 mm) and the outer wall by 0.7 K. So the exit code, the written final time and finite fields say nothing about convergence; only the log does.

Other observations: `maxOuterIter` 1 still runs two iterations per step (the loop's minimum); setting `T` and `relT` to 0 changes nothing, because `absErrT` is exactly 0 once a step has settled and 0 <= 0 counts as converged (forcing non-convergence needs the cap, or a negative `absErrT`). All runs, converged or not, exit 139 after a complete write, which is the shutdown crash recorded above; the fatal exits seen in the earlier failure probes (1, 134, 136) all came before any result was written.

**Predicate implemented 2026-10-06** (`src/core/convergence.ts`, wired into `src/core/runManager.ts`; tests `tests/convergence.test.ts` on the real probe logs saved in `tests/golden/offbeat-convergence/`, and the run manager tests). A run is a result only if the last outer iteration of its final time step (a steady case) or of EVERY time step (a transient case) meets OFFBEAT's own thermal criterion, applied to the numbers OFFBEAT printed for that iteration (`absErrT`, `relResidualT`, the initial residual of the first T solve) with the tolerances in THAT run's `inputs/system/fvSolution`; otherwise the run is `failed` with `E_NOT_CONVERGED`, the numbers in the message, the residual lines kept as the native evidence, and no result. A log with no outer-iteration records, a last iteration missing one of the three numbers, or a missing or unreadable `fvSolution` cannot be judged and is refused as `E_OUTPUT_INCOMPLETE`. A residual that is not finite is never converged (OFFBEAT's own `absErr > tolerance` would call NaN converged). The exit-status rule is narrowed too: only exit 0 and 139 are accepted after a complete write, and a `FOAM FATAL` in the log fails the run whatever the exit code. Limits: the check is thermal only (FEED switches the mechanics off), it judges the criterion OFFBEAT itself uses and not accuracy (an iteration count that satisfies it is converged, not necessarily correct), and a case with `nCorrectors` above 1 for T is read by OFFBEAT's convention (first inner iteration's initial residual, last inner iteration's other numbers). The real solver passes it: the whole suite with `FEED_SOLVER=1` (613 tests), including real steady runs and the 1000-step pulse.
