# Codex review of the additions of 2026-10-17

Five Codex reviews (model `gpt-6-sol`, read only, effort high) of what was merged or about to be merged on 2026-10-16 and 17: the four ready branches (plan 15 B4 to B7, the face between layers, the interface allowance, the flaky-test fixes), the plate stack's two-dimensional reference (B1 to B3), the particle mechanics reader and the pebble, the new case types and the population route (security boundary), and the mechanics and the compact against their plans (specification gaps). Their diffs were cut by path to fit the 120 000 character limit of the review script, so a file that is not named below was not read by a reviewer. Each finding was checked against the code here before it was acted on; the result is below. The raw findings are not kept (they are not the project's record); the table is.

**How a finding was judged.** *Confirmed and fixed*: reproduced (a script or a read of the code), fixed, with a test that fails without the fix (`tests/codexFixes.test.ts`). *Confirmed, a design limit*: true as described, a stated choice of the plan, written down as open. *Not checked*: judged from the finding's own text only; said so.

| # | Finding (location) | Verdict | What was done |
|---|---|---|---|
| R1-1 | The check response and a steady plate run solve the steady two-dimensional reference on the server thread with no bound but 20000 unknowns (`server.ts`, `stackReference.ts`) | **Confirmed and fixed.** Measured: 50 layers of 130 cells with k(T) took 27 s there; 50 layers of 400 cells did not finish in 200 s | A bound on the banded-solve work (layers x (cells of a layer)^3 at most 2e7: 50 layers of 26 cells are 9e5 and take 30 ms); a case over it keeps the allowance with the reason, in the check (`axialField2d`) and in a run. The coupled-steady-start diagnostic of a transient has the same bound |
| R1-2 | In source mode the transient reference's deadline covers the transient solve only, not the initial field or the coupled start (`stackReference.ts`, `independentRunner.ts`) | **Confirmed, minor.** In the server the runner's timer terminates the worker at the deadline whatever it is doing; only the in-process fallback (tests, no worker) can overrun | The coupled start is bounded by R1-1's cap. Otherwise accepted |
| R1-3 | A failed coupled-start solve is swallowed: `startDistance` is null without a reason (`stackReference.ts`) | **Confirmed, low.** The record says null, as for a transient that starts uniform | **Fixed** (2026-10-20, tests/codexFixesOpen.test.ts): the record carries `startDistanceReason` |
| R2a-1 | The half-step estimate of the `timeStep` check is the slice's own one-dimensional half-step run plus the coarse two-dimensional offset, which cancels in the difference: the check measures only one-dimensional time error (`stackReference.ts` `sliceIndependent`) | **Confirmed, a design limit.** The code says so (the radial mesh and the Euler step "do not depend on the conduction along the height to first order") and plan 15 B3 chose it for cost. It can fail for a short plate or a sharp local peak, where the conduction changes the field quickly | **Fixed** (2026-10-20): the worker also solves the stack at half the step and on twice the cells and the checks cut those; the reference is about 7 times the work (the largest case allowed about 25 s of the 60 s deadline). The older carried-over form stays for a solution without them |
| R2a-2 | The same for the spatial estimate of `crossCheckFv` (the doubled-mesh offset is the same in both fine cells and cancels on averaging) | **Confirmed, the same design limit** | **Fixed** with R2a-1 |
| R2b-1 | A case with free strains whose `epsilonSwelling` was not collected is `completed` with a failed check (`runManager.ts`, `trisoMechanicsResults.ts`) | **Not a defect by this project's convention:** a failed check is a result, as for a pin; the run is not "incomplete". Not checked beyond the finding's text | None |
| R2b-2 | The mechanics reader projects the displacement on the radius and reads only the diagonal stress, so a perpendicular displacement or a shear stress could be anything (`trisoMechanicsResults.ts`) | **Not checked by me.** Plausible: the checks are on the radial/tangential components | **Fixed**: check `mechanicsOffAxis` (perpendicular displacement 1e-6 of the layer + 1e-12 m, shear 1e-6 of the scale + 1 Pa; measured on the six saved runs 1e-25 m and 5.5e-8 Pa) |
| R2b-3 | The free-strain check compares only the diagonal of `epsilonSwelling` | **Not checked by me**; same family as R2b-2 | **Fixed** with R2b-2: the off-diagonal swelling strain is compared with 0 |
| R2b-4 | The mechanics bounds use the largest temperature step of the output `T` under test, so a damaged `T` can inflate them (`trisoMechanicsResults.ts`) | **Not checked by me.** Partly guarded: `mechanicsTemperature` fails in that case | **Fixed**: the bounds use the case's own temperature of each cell |
| R3-1 | Every population request starts a worker at once, with no limit and no cancel on disconnect (`server.ts`, `populationRunner.ts`) | **Confirmed and fixed** | At most 2 at once (`POPULATION_MAX_JOBS`); the next is answered 429 `busy` at once. Cancel on disconnect **fixed** 2026-10-20 (the request's close event stops the worker) |
| R3-2 | Without the compiled worker the route runs the batch on the server thread with no deadline (`populationRunner.ts`) | **Confirmed and fixed** | The route refuses with 503 `no-worker` when the worker is not built (the in-process mode stays for tests) |
| R3-3 | A compact with packing fraction 5e-324 is accepted with an infinite power per particle (`compact.ts`) | **Confirmed and fixed** (reproduced: `ok`, `particlePower` Infinity, only `W_POWER_RANGE`) | Packing fraction at least `PACKING_MIN` = 0.001 (`E_OUT_OF_RANGE`); a non-finite power per particle or kernel power density is refused |
| R3-4 | A population draw's kernel and layers are each checked against the length range, their sum (the outer radius) is not (`trisoPopulation.ts`) | **Confirmed, but not a defect.** An ordinary case is checked the same way (each length against 1 nm to 1 km, `parseTrisoGeometry` sums without a range), so the population is no looser than the validator; the range is wide on purpose. A first fix (the sum checked in the population only) was written and taken out again: it made the population stricter than the case it draws from | None |

| R4-2 | The two-scale hottest particle can heat its kernel above the kernel's stated conductivity range with no finding, because only the homogenised solid's range is checked (`compact.ts`) | **Not checked by me.** Plausible from the code's structure | **Fixed**: check `twoScaleRange` for the kernel and each layer of each two-scale particle |
| R4-3 | The sourced SiC expansion's stated range (to 1573 K) has no machine-readable form, so `W_EXPANSION_RANGE` cannot fire for the constant coefficient (`library/coatings.json`) | **Not checked by me** | **Fixed**: the three PARFUME SiC segments state the coefficient as a linear law with b = 0 over 22 to 1300 C |
| R4-4 | A `compact` block on a coated particle is silently ignored (`validate.ts`) | **Confirmed and fixed** (reproduced: accepted, no warning) | Refused: `E_UNSUPPORTED` at `/compact`. The compact pin and the pebble (which use the block) are unchanged |
